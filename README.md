## **프로젝트 소개**

Chill Stock은 소상공민과 중대형 마트의 식자재를 대신 보관하고 출고하는 서비스 를 제공하는 콜드체인 기반 3PL(Third Party Logistics) 마이크로풀필먼트 시스템 입니다.

본 프로젝트는 식재료의 특성상 중요한 온도 관리와 신선도 유지를 핵심으로 하며, 제3자 물류 운영을 통해 마이크로 풀필먼트와 콜드체인을 연결하여 효율적인 식자재 물류 서비스를 구현했습니다.

주요 구현 기능은 다음과 같습니다:
* **자동화된 입고 처리**: 제품 온도 조건과 공간 가용성을 고려한 자동 구역 배정
* **실시간 재고 관리**: 입출고 시 즉시 반영되는 재고 수량 및 이력 추적
* **콜드체인 시스템**: 온도별 보관 구역 분리 및 자동 온도 조건 매칭
* **동시성 제어**: 다중 관리자 환경에서의 안전한 승인 처리
* **지능형 반려 시스템**: 반려 사유별 코드화를 통한 체계적 거부 사유 관리
* **사용자 선택 피로 최소화**: 자동화를 통한 의사결정 지원

이를 통해 신선도, 정확성, 편리성, 확장성의 4가지 핵심 가치를 구현하며, 
현실적인 물류 자동화 프로세스와 콜드체인 물류의 특수성을 반영한 시스템을 설계하고 구현할 수 있었습니다.

## **⚙ 프로젝트 내 역할 및 기여**

### 콜드체인 기반 자동 구역 배정 로직 설계
* 입고 요청 시 제품의 보관 온도 조건, 사용자 위치, 공간 가용성을 종합적으로 고려하여 최적의 보관 구역을 자동으로 배정하는 알고리즘 구현
→ 관리자가 수동으로 구역을 선택할 필요 없이, 시스템이 자동으로 최적 위치를 결정하여 업무 효율성 극대화

### 동시성 제어 및 트랜잭션 안전성 보장
* 여러 관리자가 동시에 같은 입고요청을 승인할 때 발생하는 동시성 문제를 `@Transactional` + `FOR UPDATE` 배타락으로 해결
* 승인 처리 전 상태 재검증을 통해 이중 승인 방지 및 데이터 무결성 보장
→ 멀티 사용자 환경에서도 안전한 트랜잭션 처리 구현

### 실시간 데이터 갱신 및 사용자 경험 개선
* 입출고 이력 페이지에서 5초마다 테이블 데이터만 자동 갱신하여 실시간성 확보
* 전체 페이지 리로드 방식에서 부분 업데이트로 전환하여 서버 리소스 최적화
→ 사용자가 수동으로 새로고침하지 않아도 최신 정보를 실시간으로 확인 가능

### **체계적인 반려 관리 시스템 구축**

* 반려 사유별 코드화 시스템 도입: 공간 부족, 온도 조건 불일치, 보관 불가 제품 등 반려 사유를 코드로 분류
* 자동 반려 로직 구현: 시스템이 조건을 판단하여 자동으로 적절한 반려 코드와 함께 요청 거부 처리
* 반려 이력 추적 기능: 관리자가 반려 패턴을 분석하여 창고 운영 개선점 도출 가능
→ 단순한 승인/반려를 넘어 구체적이고 추적 가능한 거부 사유 관리 시스템 구현

## **기술적 이슈 및 해결 과정**

### **1. 동시성 문제 해결**
**문제상황**: 여러 관리자가 동시에 같은 입고요청을 승인할 때 재고 중복 반영 및 상태 충돌
```java
// 해결방안: 배타락과 상태 재검증
@Transactional
public void approveInbound(Long inboundId) {
    // FOR UPDATE로 배타락 설정
    InboundRequest inbound = repository.findByIdForUpdate(inboundId);
    
    // 상태 재검증으로 이중 승인 방지
    if (inbound.getStatus() != InboundStatus.PENDING) {
        throw new IllegalStateException("이미 처리된 요청입니다.");
    }
    
    processApproval(inbound);
}
```

### **2. 반복적인 DB 조회 최적화**
**문제상황**: 반복문에서 매번 DB 조회로 인한 성능 저하
```java
// 해결방안: 캐시 도입
@PostConstruct
public void init() {
    List<Storage> storageList = repository.findAll();
    this.storageCache = storageList.stream()
        .collect(Collectors.toMap(Storage::getId, Function.identity()));
}
```

### **3. 인증 시스템 구조 개선**
**문제상황**: 세션 확장성과 JWT 보안성 트레이드오프
**해결방안**: Redis 기반 세션 클러스터링 + Refresh Token 하이브리드 방식 도입

## **느낀 점**

이번 프로젝트는 단순한 CRUD를 넘어서 실제 물류 도메인의 복잡성과 비즈니스 로직 자동화의 중요성을 깊이 체감할 수 있었던 의미 있는 경험이었습니다.

콜드체인과 물류 도메인에 대한 이해를 바탕으로 프로젝트를 진행하면서, 현실 세계의 비즈니스 프로세스를 코드로 추상화하는 것이 얼마나 중요하고 어려운 일인지 깨달았습니다. 특히 식재료의 온도 조건, 보관 공간 제약, 사용자 위치 등 다양한 변수를 고려한 자동 배정 알고리즘을 설계하면서, 도메인 전문성이 좋은 소프트웨어 설계의 전제 조건임을 체감했습니다.

동시성 제어 구현 과정에서는 이론으로만 알고 있던 배타락, 트랜잭션 격리 수준, 데이터 무결성이 실제 서비스에서 얼마나 중요한지 직접 경험할 수 있었습니다. 특히 멀티 사용자 환경에서 발생할 수 있는 경쟁 상태를 예방하는 것이 단순히 기능 구현만큼이나 중요하다는 점을 깨달았습니다.

사용자 선택 피로 최소화라는 UX 관점에서 접근하여 자동화 로직을 설계한 경험도 매우 값졌습니다. 학술 논문을 참고하여 선택혼란, 결정장애, 구매지연이라는 심리학적 개념을 시스템 설계에 적용해보며, 기술적 구현과 사용자 경험의 균형을 맞추는 것의 중요성을 배웠습니다.

반려 코드 시스템 구축 경험을 통해서는 사용자 친화적인 오류 처리의 중요성을 깨달았습니다. 단순히 "승인" 또는 "반려"로만 처리하는 것이 아니라, 왜 반려되었는지에 대한 구체적인 사유를 코드화하여 제공함으로써 사용자가 다음 액션을 예측하고 개선할 수 있도록 도왔습니다. 이 과정에서 시스템의 투명성과 사용자 교육 효과가 얼마나 중요한지 체감할 수 있었습니다.

성능 최적화 경험을 통해서는 확장성 있는 코드를 작성하는 것의 중요성을 체감했습니다. 초기에는 단순한 반복문으로 구현했던 로직이 데이터가 늘어나면서 성능 병목이 되는 것을 확인하고, 캐싱 전략과 쿼리 최적화를 통해 해결하는 과정에서 점진적 개선의 가치를 경험했습니다.
